# 独立画布（0.6.0）

独立模式把读取、整理和画布放在本机程序中运行。Codex Desktop 更新前端资源、按钮或内部模块名时，不再需要重装这部分功能；Codex++ 不是必需组件。

## 启动

需要 Node.js 22 或更高版本，无需安装 npm 依赖。在项目目录执行：

```powershell
npm start
```

也可运行项目根目录的 `start.ps1`。打开终端打印的本机地址（包括末尾的访问令牌）。每次启动会生成新令牌；重启后请使用新的地址。不要把这个地址分享给其他人。关闭终端中的程序会停止服务。

1. 在下拉列表选择本机对话，画布自动展开；「更多」继续加载列表。
2. 打开齿轮「整理设置」，填写 OpenAI 兼容 Chat Completions 地址、模型和 API Key。
3. 点击「整理脉络」。之后用「增量整理与复盘」处理新增消息：已保存的概括会复用，再用全部概括重新编排任务树。
4. 点击任务节点查看描述、依据，并在画布的「对话原文」定位消息；支持缩放、拖动和折叠。

只有点击整理或测试连接才会发送内容至所配置的模型服务。默认不保存密钥；勾选「记住密钥」会将其明文写入本机数据目录。重试可能再次计费。

## 读取路径

- 优先启动官方 Codex CLI 的 stdio app-server，以只读方法分页读取历史，不启动或继续用户任务。
- 官方服务不可用或分页失败时，读取 `CODEX_HOME/sessions` 和 `archived_sessions` 中的 JSONL 文件。
- 分段历史按元数据中的字节边界连接，检查记录编号连续性，排除旧片段退休后的尾部。未写完的当前尾行留待下次读取；缺片段、重复编号或损坏的完整记录明确报错。
- 对话打开时定期检查已保存的消息；读取未变化的本地文件时复用缓存，官方已完成轮次也复用缓存。
- 读取失败时如有独立模式保存的快照，显示快照并标出离线状态。它不是最新完整历史的证明。

官方 CLI 可选：找不到时仍尝试本地文件。Windows 支持常见 npm 安装及显式 exe 路径：

```powershell
$env:CANVAS_CODEX = 'C:\path\to\codex.exe'
$env:CODEX_HOME = 'C:\Users\your-name\.codex'
$env:CANVAS_DATA_DIR = 'F:\canvas-data'
npm start
```

仅设置需要覆盖的项。默认 Codex 数据目录是用户主目录下的 `.codex`，独立画布目录是 `.conversation-canvas`。数据目录不应放进 Git 或共享磁盘。

## 保存与兼容边界

任务树、批次进度、设置和原文快照保存在独立数据目录中，采用临时文件写完后替换的方式保存。Codex 的更新或 userscript 重置不会清除此目录。复制该目录可备份；包含原文以及可能显式保存的密钥，应按私人数据保管。

旧 userscript 的 IndexedDB 与独立模式不共用。原有结果保留在原应用内；当前未提供旧结果自动迁移。独立模式第一次选择对话，需要重新整理。

没有任何非官方扩展能保证对未来所有格式变化永久兼容。这里消除了核心流程对 Desktop 私有前端模块的依赖；官方协议或历史文件格式发生根本变化时，读取适配器仍可能需要更新。实验性分页方法不可用时使用本地文件兜底，无法证明片段完整时停止读取。

只支持当前主机已落盘的用户／助手文字，不解析工具输出和图片语义。远程与云端任务不能仅凭本机不完整副本承诺全量支持；需要在保存历史的主机运行读取服务。独立模式定位自己的原文视图，不依赖或保证跳转 Desktop 内部消息位置。原生标题栏入口属于原 userscript，可单独使用，但仍可能需要 UI 适配。

## 验证

```powershell
npm test
npm run build
npm run demo:standalone
```

最后一项使用临时数据和模拟模型，不调用任何外部服务。打开输出地址，设置任意 HTTPS 示例地址、模型和测试密钥即可整理三条模拟消息。按 Ctrl+C 停止并清理该演示创建的临时目录。

自动测试覆盖分段合并、缺失编号、损坏记录、追加尾行、官方读取、来源访问限制、API 错误脱敏和服务重启后的存储恢复。真实外部 API 的模型质量、额度和延迟需要使用自己的配置验证。


本次本机核验：Codex CLI 0.146.0；真实长对话的官方分页与两个本地历史片段还原均得到 227 条消息，正文、顺序和来源 ID 逐条一致。浏览器已验证模拟 API 整理、树状分支、缩放、节点原文定位及刷新恢复。未调用真实付费 API。

## 在 Codex 内打开弹窗（0.4.1）

已有 Codex++ 时，在仓库目录运行 `./install-desktop.ps1 -AutoStart`。安装器备份现有 `conversation-canvas.user.js` 到 `%LOCALAPPDATA%/conversation-canvas/backups`，并安装 `public/canvas.desktop.user.js`。后台会连接已存在的本机调试端口，不启用新的远程调试访问，不修改 Codex 安装文件。`-AutoStart` 创建当前用户 Startup 文件夹中的 `Conversation Canvas.lnk`，指向本仓库 `start-desktop.ps1`；仓库及其所在磁盘必须可用。

在右上角点击分支图标，画布以页面内弹窗显示。关闭、Escape 和背景点击可返回主对话。当前任务通过地址和可见选中侧栏项识别；无法识别时提供本机对话选择。服务未连接时会明确提示启动后台，避免一直等待。

后台采用 Chromium 标准的 Runtime binding 与重载注入，桥接只允许读取历史、保存画布和请求模型这些限定操作。模型流由本地服务转发，不经过 Desktop 私有 HTTP 模块。关闭或重载窗口会中断未完成请求；已提交批次保留。标准连接或上游历史格式变更仍需维护；这里消除的是核心流程对 Desktop 前端构建版本的绑定。

后台日志在 `%LOCALAPPDATA%/conversation-canvas/desktop.log` 与 `desktop-error.log`。如不需要登录启动，移除 Startup 中的上述快捷方式即可。停止后台或恢复旧脚本前请先暂停整理；备份保留在上述目录。原生模式与桥接模式不要同时启用两份画布脚本。

验证：84 项自动测试通过；禁用 iframe 的模拟页面验证了打开、整理、刷新恢复和关闭弹窗，主对话草稿保留。真实 Codex 中确认只有一个按钮且桥接可读出长对话；未发送真实对话到付费 API，也未重启用户正在工作的 Codex 来测试启动流程。

## 整理后的逻辑复盘（0.4.2）

点击「整理脉络」会先完成来源片段归纳，再自动启动第二轮逻辑复盘。复盘遍历全部任务节点，结合树目录、当前页及祖先和有限原文摘录，优化父子归属与标题、摘要、详情，明确「目标→方案→尝试→结果→下一步」。大树分批复盘，不会要求模型一次返回整棵树。状态与原文证据不能被复盘改写，结构必须通过单根、无环和来源校验。复盘页进度单独保存；未完成时继续显示之前的画布，全部通过后再发布优化结果。

已整理的旧画布再次点击主按钮，也会补上这一轮复盘。同一份已复盘原文不会重复付费复盘；新增内容整理后会重新复盘更新后的树。复盘会增加模型请求与费用，自动检查结构和覆盖并不能保证模型的每项语义判断都正确。

API 请求默认设置 8192 输出 token 预算；外接整理每批最多 12 个片段，复盘每页最多 8 个节点，并限制输出字段长度。输出长度上限、HTTP 413 或结果过大时自动缩小批次；单条长消息必要时进一步按原文位置拆分，保存拆分映射供续传使用，最小片段仍失败时明确停止。已完成片段保留，不重复提交整份历史。

流式解析分别限制累计传输量（64 MiB）、单条流事件或非流式 JSON（2 Mi 字符）、实际正文（256 Ki 字符）。推理和流式包装不会再直接消耗旧的 4 MiB 正文额度；这些边界仍会限制异常输出。新版已通过 88 项自动测试及模拟 API 的完整「整理→复盘→保存」界面验证，未使用真实付费 API 验证语义质量。


### 0.4.3 对话材料过滤

整理与复盘不读取生成文件。发送模型前过滤附件元数据、纯文件链接清单、大段围栏内容及助手的实现代码；保留讨论正文、短用户示例和关键报错行。原始消息和引用位置保持不变。纯产物消息不显示为待整理。旧版本结果在下一次整理时自动重建，完成前仍显示旧结果；新规则下可断点续整。过滤是保守规则，正文中的文件讨论和未标记为代码块的内容仍可能保留。

### 0.5.0 并行事实概括

第一阶段按用户请求和后续助手消息分组，单请求最多 10000 字符或 8 个原文片段，并附前组末尾的简短上下文。结果按片段校验字段和来源，每份保存；暂停保留未完成请求标识，失败等待在途任务保存后返回。写入队列串行提交，避免并行检查点互相覆盖。

第二阶段在 0.6.0 起一次读取全部概括编排整棵树；输入过大先压缩，输出过大先生成骨架。第三阶段使用原文依据复盘。来源 ID、原始范围和覆盖检查保持不变。超大概括请求先拆组，单片段仍超限则回退原有原文缩批机制。旧版已经完成的节点可直接增量续整。未完成 API 请求重发可能重复计费，缓存避免重复处理已保存概括。

### 0.6.0 全局编排检查点

全局结果以 manifest 为快照标识；暂停保留请求 ID、压缩位置与已经完成的压缩组。若期间增加消息，将沿用逐片段概括缓存并重新生成全局请求，避免把旧快照当成完整新结果。模型必须覆盖所有概括来源，压缩后的别名由程序展开为原始片段及其字符位置。来源不完整、孤立父节点或循环关系均不发布；格式补正最多一次。压缩无法进一步缩小时明确报错并保留工作，不丢弃尾部。骨架必须完成描述复盘后才作为最终结果发布。
